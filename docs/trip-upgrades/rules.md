# Rules for every step

## Building

1. **Read first:** `mobile/AGENTS.md`, `docs/architecture.md`, `docs/technology-decisions.md`, this folder's `README.md`, the sections of `features.md`, `design.md` and `decisions.md` that the step names, and the previous step's report. Routes stay in `mobile/app/`. **Never hand-edit `mobile/android/`** (it's generated by `npx expo prebuild`).
2. **No fake data.** Every value shown comes from the API or the traveller. Unknown prices, hours and ratings stay unknown and say so. A "not checked" badge marks anything outside Vromon's reviewed data.
3. **Optional means optional.** No new required question anywhere. A traveller who answers nothing gets today's behaviour (hotel by budget, restaurants for every meal, today's search).
4. **Privacy is enforced on the server.** Every new endpoint gets the privacy matrix tests listed in `design.md` §3. Family/friend homes follow D2.
5. **Every string goes through i18n**, in English and Bangla, with Bangla digits (`usePlanFormat`). `src/__tests__/translations.test.ts` must keep passing.
6. **Accessibility:** 48 dp touch targets, labels on icon buttons, AA contrast (new tokens in `src/__tests__/contrast.test.ts`), a non-gesture route for every gesture.
7. **Maps:** a map that gets overlays (sheets, cards) mounted after it uses `androidView="texture"`, as `DayMap.tsx` does. The default GLSurfaceView painted over the plan sheet in release builds.
8. **Formatting:** there's no prettier config. Format only files you create (`prettier --single-quote --print-width 160 --trailing-comma all`). Edit existing files by hand in their own style; never re-wrap whole files.
9. **Dependencies:** add Expo packages with `npx expo install`. A new native module means rebuilding the dev app (`./gradlew assembleDebug -PreactNativeArchitectures=arm64-v8a` in `mobile/android`, then `adb install -r`) and the friends' APK at the end (step 8).
10. **Before reporting a step as done**, run:
    - `mobile/`: `npx tsc --noEmit` (route-type errors about `/explore/*` and `/trip/journey/*` come from stale generated types and clear when Metro starts), `npx eslint <changed files>`, `npx jest`. Baseline 2026-11-12: 575 passed; `chatCache.test.ts` "a page of older messages…" is flaky under the full run and passes alone.
    - `backend/`: `venv/bin/python -m pytest -q`. Baseline: 747 passed, 9 skipped. New migrations must pass `tests/test_migrations.py`.
    - `data-platform/` (if touched): `.venv/bin/python -m pytest -q`. Baseline: 55 passed.
11. **Do not commit, push or open a PR.** End the report with the git commands for the owner to run.
12. **End the step** with `docs/trip-upgrades/reports/step-N-report.md`: what changed and why, the files, how each part was verified (tests, API calls, phone screenshots described in words), what is left open, and the owner's open items. Update the Status table in `README.md`. Then **stop**.

## Testing safely

- **The phone is the owner's real realme phone** (USB, `adb -s b5649424`). It gets real calls. Before every tap, key or swipe, check that `adb shell dumpsys window | grep mCurrentFocus` shows the Vromon app and `adb shell dumpsys telephony.registry | grep mCallState` is `0`. Send one input, then take a screenshot. `scripts/dev/phone.sh` does these checks. Never chain taps across screens.
- **Never an emulator.**
- **Writes only as the test accounts.** They're in `.env.e2e.local` at the repo root (git ignores it; keep it out of `mobile/`). `python3 scripts/e2e/session.py A|B` prints a token; `scripts/e2e/chat_as.py` drives B from the Mac. Never print or copy the passwords.
- **The owner's account** (`alifalahadxi@gmail.com`) is for **read-only** checks: run `backend/venv/bin/python scripts/dev/readonly_proxy.py` (port 8011), then `adb reverse tcp:8001 tcp:8011`, and undo with `adb reverse tcp:8001 tcp:8001`. Signing the phone into a test account signs the owner out everywhere: tell the owner first.
- **Never "dry run" a service that commits.** `ItineraryService.generate()` commits by itself. Use the test accounts or a copy of the database (`sqlite3 "file:backend/vromon.db?mode=ro" ".backup '<scratch>/copy.db'"`).
- **Data platform runs** (step 5): first on a copy of the database (`VROMON_DATABASE_URL=sqlite:////path/to/copy.db`). Then back up the real one (`backend/vromon-backup-YYYY-MM-DD-<what>.db`) before running on it.
- **The friends' share** (`scripts/share/start.sh`) runs a second backend on port 8002 **on the same database**. Anything written in tests is visible to friends unless it's on a test account.
- **Running the app:** see `docs/running-locally.md`.
  - Backend: `backend/venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8001`.
  - Metro: `npx expo start --dev-client --clear`.
  - Ports: `adb reverse tcp:8081 tcp:8081` and `adb reverse tcp:8001 tcp:8001`. A USB reconnect drops them.
- **Release-only bugs:** debug builds can hide them, as with the plan sheet on 2026-11-12. For anything about maps, sheets or start-up timing, also check a release build of the dev app: `./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a`, `adb install -r`, repeat the action 8–10 times. `uiautomator dump` tells "drawn" from "present".
- **Maestro** (`mobile/.maestro`): run in the background. New flows are added to `flowsOrder` in `config.yaml` **by their `name:`**; renaming a flow means renaming it there too. On the owner's phone add `-e DEV_CLIENT=false`.
